# Contributing

## Reglas básicas

- La rama `main` debe permanecer estable.
- Todo trabajo debe realizarse en una rama con propósito claro.
- No usar ramas personales como `edu`, `cristian` o equivalentes.
- Los cambios importantes deben incorporarse mediante Pull Request.
- Cada Pull Request debe describir el cambio, su verificación y los riesgos conocidos.

## Nombres de ramas

- `feature/...` para nuevas funcionalidades.
- `fix/...` para correcciones.
- `test/...` para trabajo de verificación o pruebas.
- `docs/...` para documentación.
